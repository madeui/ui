
Installs `@tanstack/charts` alongside the component.

## Usage

```tsx
import {
  Chart,
  ChartContainer,
  ChartLegend,
  ChartTooltipContent,
  chartAxis,
  chartCurve,
  chartGridAxis,
  chartTheme,
  useChartLegend,
} from '@/components/ui/chart';
```

```tsx
'use client';

import { barY, defineChart } from '@tanstack/charts';
import { scaleBand } from '@tanstack/charts/scales/band';
import { scaleLinear } from '@tanstack/charts/scales/linear';
import { tooltip } from '@tanstack/charts/tooltip';

const definition = defineChart({
  marks: [barY(rows, { x: 'month', y: 'revenue', radius: 4 })],
  scales: {
    x: { scale: () => scaleBand().padding(0.3), axis: chartAxis },
    y: { scale: scaleLinear, nice: true, grid: true, axis: chartGridAxis },
  },
  theme: chartTheme,
  tooltip,
});

<ChartContainer>
  <Chart
    definition={definition}
    aspectRatio={16 / 9}
    ariaLabel="Monthly revenue"
    renderTooltipBody={(context) => <ChartTooltipContent {...context} />}
  />
</ChartContainer>;
```

`chartTheme`, `chartAxis`, and `chartGridAxis` are what make a chart look like the rest of the library — pass `theme: chartTheme` on the definition, `axis: chartAxis` on every scale that draws a labelled axis, and `axis: chartGridAxis` on the ones that only contribute gridlines.

Size a chart with `aspectRatio` rather than `height`. The server renders the whole chart, and only `aspectRatio` gives that markup a box of the same shape as the scene it laid out, so the chart is on screen and correctly proportioned before any script runs. [First paint](#first-paint) has the details.

`Chart` mounts the chart with a layout effect, so in the Next.js App Router any file that renders it must be a client component (`'use client'` at the top). Create definitions at module scope or inside `useMemo`: the definition's identity is what tells the chart to update.

## Composition

```tsx
<ChartContainer>
  <Chart renderTooltipBody={(context) => <ChartTooltipContent {...context} />} />
  <ChartLegend />
</ChartContainer>
```

## First paint

A server cannot measure the container, so the library lays the scene out at `initialWidth` (640 by default) and gives the `<svg>` a `viewBox` of that size with `width="100%" height="100%"`. The browser then fits that box into the host, and what the fit does depends on how the host was sized:

- **`aspectRatio`** sizes the host to the same ratio the scene was laid out at, so the server-rendered chart fills it edge to edge. Hydration re-renders the scene at the measured width, which changes the scale of the text and the gridlines but leaves every mark where it already was.
- **A fixed `height`** gives the host a ratio the scene does not share, so the browser letterboxes the scene inside it: the plot paints small and centred, then jumps to size when the chart mounts.

Prefer `aspectRatio` everywhere, and pass `initialWidth` as well when the layout has a usual width — the closer it is to the real one, the less the first paint differs from the settled one.

None of this needs scripting to be visible. A chart still needs it for pointer, keyboard, and tooltip behaviour, but the plot itself is server-rendered markup and shows without it.

## Line

`z` splits rows into series. With no explicit color scale, each series takes the next slot of the palette the container provides (`colors.chart1` … `chart6`). `curve: chartCurve` smooths the path, and the points stay undotted: grouped focus marks the hovered value on every line, which is the only place a dot carries information.

## Stacked area

Each layer is its palette color at 40%. A `stroke` on `areaY` outlines the layer's closed path, down both sides and along the bottom as well as over the top, so an edge only on the top of a band is not something the mark can draw.

## Donut

Polar marks come from `@tanstack/charts/polar`; `pie` allocates the angles and `radialArc` paints them. `stroke: colors.background` separates the slices, and the centre total is HTML stacked over the plot — the library paints no centre label.

## Legend

`useChartLegend` reads the chart's resolved color scale through `onRender` and returns the items for `ChartLegend`. Items keep their identity until the domain or its colors change, so the legend does not re-render on every chart paint.

`formatter` receives the row's formatted value, its label, and the chart point behind it — read the raw `yValue` from the point when formatting numbers.

## Sparkline

`guides: false` and `margin: 0` let the plot fill its box; `pointer: false` and `keyboard: false` turn off focus for a purely decorative chart. The scale spans the data rather than starting at zero — a sparkline reads as shape, and a zero baseline flattens it.

The fill is a gradient: `gradients` on the definition puts a `<linearGradient>` in the scene's defs and a mark reaches it with `fill: 'url(#id)'`. Keep gradient fills to marks whose points are never named in a tooltip or a legend — the library takes a point's color from its resolved fill, so `url(#id)` would reach the swatch, which cannot paint it.

## API reference

Built on [TanStack Charts](https://tanstack.com/charts). `Chart` takes the props of the library's React component (the tooltip-capable entry from `@tanstack/charts/react/tooltip`) — `definition`, `ariaLabel`, `height`, `aspectRatio`, `width`, `initialWidth`, `onRender`, `renderTooltipBody`, the focus callbacks — all documented in the [TanStack Charts React reference](https://tanstack.com/charts/latest/docs/framework/react/reference/chart). Definitions, marks, scales, and the `tooltip` extension are the library's API as well.

No part takes `variant` or `size`: a chart has no meaningful preset axis, and sizing belongs to `Chart`'s own `aspectRatio`, `height`, and `width` props.

### Chart

`Chart` supplies one `renderSvg`, which does two things the library has no other hook for.

The chart surface carries the focus-visible ring. The library renders the plot as an `<svg>` with `tabindex`, which the browser rings with its own outline on every click; the house ring goes on that element instead, so the ring appears on keyboard focus only.

The gridlines are restyled. The library paints them from `theme.grid` at a fixed 11% opacity and stroke width 1, and a scale's `grid` is a plain boolean, so their weight and dash have no option. `renderSvg` receives the scene before it is serialized, and its node styles are public, so the grid group is given `colors.border` at full opacity as a dashed hairline on the way through.

Passing your own `renderSvg` replaces both.

Sizing is the library's own: see [First paint](#first-paint) for why `aspectRatio` is the one to reach for.

### chartTheme

Scene colors for `defineChart({ theme })`: gridlines, axis text, and focus guides in the design tokens instead of the library's defaults. The library paints each role at a fixed opacity, so `grid` is `colors.foreground` at the 11% the library applies, which lands on `colors.border` — the value a chart falls back to when `renderSvg` is replaced and the gridlines are not restyled.

### chartAxis

Axis presentation for a scale's `axis` option: the gridlines carry the structure, so the domain line and tick stubs are off, and tick labels sit at the caption size in `colors.mutedForeground`. Spread it when an axis needs more, and spread `chartAxis.ticks` too when that axis sets its own `count` or `format`:

```tsx
axis: {
  ...chartAxis,
  label: 'Revenue',
  ticks: { ...chartAxis.ticks, format: (value) => currency.format(Number(value)) },
}
```

The axis title is the one guide the library does not expose a style hook for: it renders one step below the tick labels at weight 600.

### chartGridAxis

Axis presentation for a scale whose gridlines are all that should show: no domain line, no tick stubs, no labels, and four bands of grid. A value axis behind a mark usually reads better this way, with the tooltip carrying the number.

`axis: false` also hides an axis, but it leaves the tick count to the plot height, which on a tall chart draws about twice as many gridlines as the eye needs. Spread `chartGridAxis` to change the count:

```tsx
axis: { ...chartGridAxis, ticks: { ...chartGridAxis.ticks, count: 6 } }
```

### chartCurve

Monotone cubic interpolation for a mark's `curve`, on `lineY`, `areaY`, and the other curve-taking marks. It smooths the path without letting it overshoot a data point.

```tsx
lineY(rows, { x: 'month', y: 'visitors', strokeWidth: 2, curve: chartCurve })
```

The library's own curve adapter, `d3Curve`, takes a `d3-shape` curve factory, which is a dependency this component does not install; `chartCurve` is the same construction with no dependency.

### ChartContainer

A `div` that acts as the theme bridge: it maps the design tokens onto the CSS custom properties TanStack Charts reads (the six palette slots, the tooltip chrome, the focus and crosshair fills) and sets the font and color the scene inherits. Wrap every `Chart` in one. It is a column flex box with `min-width: 0`, so the chart stays responsive and a `ChartLegend` placed after it stacks below the plot.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `style` | `StyleXStyles` | — | StyleX styles merged last — always win over the component's own styles. |

All native `div` props are forwarded.

### ChartTooltipContent

Body for `Chart`'s `renderTooltipBody`. Spread the render context straight in: `renderTooltipBody={(context) => <ChartTooltipContent {...context} />}`. The chart keeps ownership of focus, anchoring, placement, pinning, and dismissal; this renders the title and one swatch + label + value row per focused series.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `content` | `ChartTooltipContent \| string` | — | The tooltip model from the render context (required). |
| `points` | `readonly ChartPoint[]` | `[]` | Focused points from the render context, matched to rows by index. |
| `indicator` | `'dot' \| 'line'` | `'dot'` | Swatch shape next to each row. |
| `formatter` | `(value: string, name: string, point?: ChartPoint) => ReactNode` | — | Replaces a row's formatted value. |
| `hideLabel` | `boolean` | `false` | Omits the title (the shared axis value on grouped focus). |
| `style` | `StyleXStyles` | — | StyleX styles merged last — always win over the component's own styles. |

`defaultBody`, `pinned`, and `dismiss` from the render context are accepted and ignored so the context can be spread without picking fields.

### ChartLegend

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `items` | `{ label: ReactNode; color: string; key?: string }[]` | — | Legend entries (required). `color` is any CSS color, including the palette references the chart resolves. |
| `align` | `'start' \| 'center' \| 'end'` | `'center'` | Horizontal alignment of the row. |
| `style` | `StyleXStyles` | — | StyleX styles merged last — always win over the component's own styles. |

All native `div` props are forwarded.

### useChartLegend

```ts
const { items, onRender } = useChartLegend();
```

| Value | Type | Description |
| --- | --- | --- |
| `items` | `readonly ChartLegendItem[]` | One entry per value of the chart's resolved color domain, colored with the scale's own mapping. |
| `onRender` | `(context) => void` | Pass to `<Chart onRender={onRender} />`. Compares the domain by value and only produces new `items` when it changes. |

### Styling

`ChartContainer`, `ChartTooltipContent`, `ChartLegend` accept `style` (`StyleXStyles`, merged last so caller overrides always win) plus all native props of the element they render. `Chart` takes the library's own `className` / `style` (plain CSS) — prefer styling the container.

The scene itself is painted by the library, not by CSS, so its colors come from `chartTheme` and the six palette slots `ChartContainer` maps onto the library's custom properties. Mark styling — stroke widths, fill opacities, bar radii and insets, curves — belongs on the marks in the definition, and scene sizes there are plain numbers in SVG user units rather than tokens.
